# Compact Excel-style settlement popup — 26 October 2026

The user's sample selects an in-page summary: View summary opens the existing Radix Dialog with a bill selector, bill name/date, original supplier payer names, one row per member, actual item columns, Total and a total footer. The reference fixture reproduces Marcus 10.50, YT 9.80, ET 10.80, ZOEY 13.00, REYES 16.60, CALVIN 12.80, YH 14.30 and RM87.80 total. Final suggested payments are collapsed and explicitly labeled as all bills; selected-bill consumption is not represented as the amount owed after group offsets.

- KEEP: calculate/ledger amounts, existing authorization and bound personal projection, original expenses/payments, the CSV function and existing themes. This change is read-only with no endpoint, role, schema, dependency, secret or audience change.
- CHANGE NOW: replace the external CSV/long-print entries with one View summary entry. Keep Print / Save PDF and CSV inside the popup. The selected sheet prints directly through an isolated srcDoc iframe, without downloading/opening an HTML file first. It contains no executable content or remote resources; HTML is escaped and CSP/sandbox restrict the document. Existing unmatched repayment review is included in scoped popup/print output. The old full-report generator is archived, not mounted.
- Privacy/correctness: Mine filters bill options and rows, and direct lookup of an unrelated bill returns null. Personal exports use only the existing authorized personal expense projection. Currency labels distinguish original item values from settlement-currency consumption. Adjustment reconciles vouchers/refunds/prepaid timing without inventing a separate bill calculation. No payment is created by opening, switching or printing. Selected calculation is lazy; the whole ledger is not recomputed to populate this UI.
- Responsiveness/recovery: bounded modal height, internally scrollable table with sticky names/header, visible close/escape behavior, and retained print controls. Print waits for the iframe load; unavailable print APIs show a retry message. Selected bill falls back to an existing bill if a refresh removes it. Native print completion is outside the app's control. No transient preview or bill state is written into shared data.

Added reference amounts, scope boundaries, personal redaction, FX/adjustment conservation, deleted bills, escaped print text, continuation tables and repayment review coverage. Actual handset/native print output and physical pagination remain unverified. Production build and Worker smoke are packaging gates.
