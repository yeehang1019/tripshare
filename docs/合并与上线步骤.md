## 步骤 1：审核并合并 Pull Request

1. 打开 [yeehang1019/tripshare#1](https://github.com/yeehang1019/tripshare/pull/1)。
2. 看一下 "Files changed"。主要改动在这些文件：
   - `lib/amount-expression.ts`
   - `app/trip-controls.tsx`
   - `app/expense-editor.tsx`
   - `lib/settlement-outstanding.ts`
   - `app/settlement-payments.tsx`
   - `app/trip-app.tsx`
3. 确认 PR 页面显示可以合并（没有冲突）。
4. 按 **Merge pull request**。

## 步骤 2：发布网站

1. **先记下目前线上的版本号，** 用来回滚。
2. 用平时的 **Sites 发布流程**，发布合并后 `main` 的最新提交。远端会自己执行 `npm run build`。
3. 保持目前的网站访问权限设置不变，不要改成公开或改动访问范围。
4. 记下新的版本号。

## 步骤 3：上线后检查（只在 QA Test 空间操作）

> ⚠️ **只能在 QA Test 空间新增或修改数据。** KL House、Thailand 等真实空间只能看，不能写入。

| # | 操作 | 预期结果 |
|---|---|---|
| 1 | 新增一笔 **THB** 账单，不填汇率 | 不能保存，提示要填汇率；"More options"自动展开 |
| 2 | 在"1 MYR = ? THB"填 `7.5`，金额 1000 | 显示"≈ RM 133.33"，可以保存 |
| 3 | 金额栏输入 `12,50`，然后点别处 | 出现红字"Use a dot for decimals"，不能保存 |
| 4 | 打开付款对话框，金额输入 `12,50` | Confirm 按钮变灰。**不要按 Confirm** |
| 5 | 建两笔方向相反的账单：A 付款 B 吃，再 B 付款 A 吃 | 结算页按"Prepare WhatsApp summary"，文字里有"(Offset RM … each way: …)" |
| 6 | 结算页选"Mine"，而且你同时有要付和要收的款项 | 分开显示"You pay"和"You receive"，不是一个相加的数字 |
| 7 | 在首页饼图点任意分类，再回到首页 | 饼图仍然显示全部分类，没有缩小 |

检查完后，删除 QA Test 里新增的测试账单。

- **金额、权限或结算数字不对：** 立刻切回步骤 2 记下的旧版本，并把截图发给我们。
- **只是画面排版问题：** 不用回滚，截图告诉我们即可。
