## 一句话总结

TripShare 的账本算法本身是正确的。这次修的问题都出在两头：**数字怎么输入进去**，以及**数字怎么显示和导出**。有几处会让人在不知情的情况下存错金额，或者看到错误的合计。

这次**没有改动**账本算法、API、数据库结构、权限或任何已存的数据。

---

## 最重要的 5 个问题

| # | 问题 | 修改前 | 修改后 |
|---|---|---|---|
| 1 | 小数用了逗号 | 输入 `12,50` 会存成 **RM 1,250.00**（多了 100 倍），没有任何提示 | 提示"Use a dot for decimals"，改正前不能保存 |
| 2 | 外币没设汇率 | THB 1,000 按 1:1 记成 **RM 1,000** | 必须先填汇率才能保存；可以用"1 MYR = 7.5 THB"的方式填，并即时显示"≈ RM 133.33" |
| 3 | 设置页偷偷写入假汇率 | 切换默认币种时，会把这个币种的汇率存成 1，连之前保存的真实汇率也被覆盖 | 不再写入；旧数据里的 1 会被当作"还没填汇率" |
| 4 | 付款对话框 | 输入 `12,50` 会显示错误，但 Confirm 仍然可以按，并按旧金额（例如 RM 114）记账 | 金额改正前不能确认付款 |
| 5 | 只看一个人时的结算合计 | Ali 要付 45、要收 76.66，却显示"Total still to pay: **RM 121.66**" | 分开显示"Ali pays: RM 45.00"和"Ali receives: RM 76.66" |

## 全部改动

### 输入金额
- 逗号只能当千位分隔，例如 `1,250`。
- 可以直接输入 `RM 12.50`、`THB 1,000`、全角数字、`3x12`。
- `1.005` 会正确四舍五入成 1.01。以前因为浮点误差，会变成 1.00。

### 汇率
- 新增反方向汇率输入，例如"1 MYR = 7.5 THB"。
- 汇率和空间已保存的汇率相差超过 3 倍时，会提醒检查是否填反。
- 详情页的汇率不再显示 `0.13333333333333333` 这种长小数。

### 分摊
- 3 人按百分比分摊时，默认是 33.33 / 33.33 / 33.34，加起来刚好 100%。
- 自定义分摊会即时显示"已分配多少、还剩多少"，并有"把剩下的给最后一人"按钮。
- 多人付款、请客的账单，预览里也会显示"谁要还谁多少"。

### 结算导出（复制、WhatsApp、CSV、打印）
- 只看一个人时，"要付"和"要收"分开显示；"Everyone"视图仍然只有一个总额。
- 新增抵消说明，例如：
  ```
  Ali → Bob · Total: RM 45.00
  - Hotel · 02/11/2026  RM 45.00
    (Offset RM 30.00 each way: Dinner)
  ```
  账单名最多列 2 个，其余写成"+N more"。CSV 里这一栏是文字，不会被误加或误减。

### 首页和其他画面
- 首页图表不再跟着支出页的筛选变化。以前在首页饼图点一个分类后，回到首页，饼图就只剩那个分类。
- 饼图图例合并成"前 4 个分类 + Other categories"，加起来等于中间的总额。
- "vs last month"改成和上个月同一段日子比较。以前用本月几天和上月整月比，月初几乎一定显示大幅下降。
- 首页和支出页的"本月"统一按空间的时区计算。
- 外币账单在列表里多显示"≈ RM x"。
- 搜索可以用画面上显示的日期（`01/11/2026`）和金额（`12.50`）。
